# Scope Guardrails

**Version:** 0.1  
**Status:** Active draft

## 1. Purpose

Protect Sanad from uncontrolled scope expansion before the pilot validates the core provider-to-provider tele-expertise model.

## 2. Core Scope

Sanad is currently:

- provider-to-provider;
- doctor-to-doctor tele-expertise;
- asynchronous by default;
- non-emergency;
- pilot-first;
- one specialty initially;
- one state initially;
- small number of facilities;
- evidence-generating.

## 3. Explicitly Out of Scope for the Initial Pilot

- direct doctor-to-patient consultation;
- emergency dispatch;
- guaranteed 24/7 coverage;
- remote consultant prescribing directly to patients;
- patient billing;
- national rollout;
- AI diagnosis;
- autonomous clinical decision-making;
- national health information exchange;
- broad hospital EMR replacement;
- multi-country expansion;
- advanced payment marketplace;
- consumer mobile app.

## 4. Scope Change Rule

A proposed new capability must answer:

1. Is it required to test the current pilot hypothesis?
2. Does it materially improve safety or feasibility?
3. Does it introduce new legal/regulatory obligations?
4. Does it change the clinical responsibility model?
5. Does it expand data collection?
6. Does it delay the pilot?
7. Can it be deferred?

## 5. Approval

Material scope changes require product, clinical, and relevant legal/security review.

## 6. Anti-Pattern

Do not add capabilities simply because a vendor offers them or because they appear mature in competitor products.
