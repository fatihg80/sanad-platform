# Glossary

This glossary explains project terminology in plain language for clinical, public-health, operational, and technical readers.

| Term | Meaning in Sanad |
|---|---|
| Pilot | A limited real-world trial used to test the service model before wider rollout. It does not mean an aircraft pilot. |
| MVP | Minimum Viable Product, the smallest usable product capable of supporting the pilot and testing the core assumptions. |
| Tele-expertise | Remote specialist advice provided from one healthcare professional to another. |
| Provider-to-provider | A service between healthcare professionals, rather than directly between a remote doctor and a patient. |
| Structured case | A case submitted using an agreed format containing the clinical information needed for specialist review. |
| Routing | Directing a submitted case to an appropriate consultant or specialty. |
| Duty coordinator | A person responsible for operational monitoring and, where needed, case routing and escalation. |
| Asynchronous consultation | Advice provided without requiring both doctors to be online at the same time. |
| Clinical governance | The framework used to maintain clinical quality, safety, accountability, and continuous improvement. |
| Clinical audit | Structured review of selected cases against agreed standards. |
| Incident | An event that caused or could cause harm, delay, error, or service failure. |
| Near miss | An event that could have caused harm but did not. |
| Second opinion | Review of a case by another suitably qualified specialist. |
| MDT | Multidisciplinary Team, a group of professionals from relevant specialties who review complex cases together. |
| SLA / response target | The expected time within which a service response should be provided. |
| Mobile-first | Designing the primary user experience around mobile devices before larger screens. |
| Offline capability | The ability to continue selected work when internet connectivity is unavailable and synchronise later. |
| Data minimisation | Collecting only the information genuinely required for the service. |
| Data residency | The country or legal region in which data is stored or processed. |
| RBAC | Role-Based Access Control, permissions based on a user's assigned role. |
| Audit trail | A traceable record of significant system and case actions, including who performed them and when. |
| DPIA | Data Protection Impact Assessment, a formal assessment of privacy risks associated with processing personal data. |
| Indemnity | Professional protection or insurance related to liability arising from clinical practice. |
| MoU | Memorandum of Understanding between participating organisations. |
| NGO | Non-governmental organisation. |
| CPD | Continuing Professional Development for healthcare professionals. |
| Build vs Buy vs Partner | Evaluation of whether to build a product, acquire/adapt an existing product, or operate through a partner. |
| PRD | Product Requirements Document, describing what the product should achieve and for whom. |
| SRS | Software Requirements Specification, describing system behaviour and implementation-level requirements in greater detail. |
| RFP | Request for Proposal, a document asking vendors to propose how they would deliver a defined solution. |
| ADR | Architecture Decision Record, a short document recording an important technical decision and its rationale. |
| C4 | A software architecture visualisation model covering context, containers, components, and code where needed. |
