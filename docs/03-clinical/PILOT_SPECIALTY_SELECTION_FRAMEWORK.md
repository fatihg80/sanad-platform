# Pilot Specialty Selection Framework

**Version:** 0.1  
**Status:** Draft  
**Scope:** Selection of the first Sanad pilot specialty only

## 1. Purpose

Define a transparent method for choosing the first pilot specialty without expanding Sanad beyond its current provider-to-provider tele-expertise scope.

The founding prospectus identifies candidate specialties including:

- obstetrics and gynaecology;
- paediatrics;
- internal medicine;
- general surgery;
- dermatology;
- radiology.

This framework does not select a specialty yet. It defines how the founding team should make that decision.

## 2. Core Selection Principle

The best pilot specialty is not necessarily:

- the largest specialty;
- the most prestigious specialty;
- the specialty with the greatest national burden;
- the specialty with the most enthusiastic consultant.

The best pilot specialty is the one that gives Sanad the strongest chance to test the operating model safely, measurably, and realistically.

## 3. Evaluation Criteria

Each candidate specialty should be scored against the same criteria.

### A. Demonstrated Need

Questions:

- Do partner facilities report a real gap in specialist support?
- Are local doctors currently managing cases without timely consultant input?
- Is the need frequent enough to generate meaningful pilot volume?

Suggested weight: **High**

### B. Suitability for Asynchronous Tele-Expertise

Questions:

- Can a specialist provide useful advice from history, examination findings, images, and test results?
- Is live physical examination by the remote specialist usually unnecessary for the advisory question?
- Can advice remain provider-to-provider rather than direct-to-patient?

Suggested weight: **Critical**

### C. Emergency Dependence

Questions:

- What proportion of likely cases require immediate emergency intervention?
- Can the specialty operate safely within Sanad's non-emergency boundary?

Specialties that depend heavily on immediate response may be poor first-pilot choices unless case selection is tightly constrained.

Suggested weight: **Critical**

### D. Consultant Supply

Questions:

- Are enough qualified Sudanese consultants abroad willing to participate?
- Can a sustainable rota be created?
- Are relevant registrations and indemnity conditions manageable?

Suggested weight: **High**

### E. Local Doctor Readiness

Questions:

- Are local clinicians willing to use a structured digital workflow?
- Is the specialty represented at partner facilities?
- Can doctors provide the required case information consistently?

Suggested weight: **High**

### F. Diagnostic Information Availability

Questions:

- Are the tests, imaging, photographs, or observations required for remote review actually available locally?
- Can they be captured and transmitted under weak connectivity?

Suggested weight: **High**

### G. Outcome Measurability

Questions:

- Can the pilot measure whether advice changed management?
- Can follow-up outcomes be captured within the pilot period?
- Can referral avoidance or improved decision-making be observed?

Suggested weight: **High**

### H. Clinical Governance Complexity

Questions:

- How difficult is it to standardise case submission?
- Is second-opinion structure feasible?
- Are safety boundaries clear?
- Is the specialty likely to create large ambiguity around remote liability?

Suggested weight: **High**

### I. Data and Image Burden

Questions:

- Are cases dependent on very large image sets or specialist viewers?
- Will low bandwidth materially limit review?
- Are clinically important images safe to compress?

Suggested weight: **Medium to High**

### J. Existing Partner Support

Questions:

- Is an NGO or health facility already active in the target area?
- Can it support onboarding, connectivity, training, and coordination?

Suggested weight: **High**

### K. Pilot Volume Feasibility

Questions:

- Can the specialty realistically contribute enough cases to reach the intended evaluation volume?
- Is there risk of too few cases or excessive demand?

Suggested weight: **Medium**

### L. Neutrality and Access

Questions:

- Can the service be offered without appearing politically or geographically selective?
- Can participation remain consistent with Sanad's neutrality principle?

Suggested weight: **High**

## 4. Suggested Scoring Model

Score each criterion:

- 1 = Poor
- 2 = Weak
- 3 = Acceptable
- 4 = Strong
- 5 = Very Strong

Then apply agreed weights.

Example:

| Criterion | Weight | Score 1–5 | Weighted Result |
|---|---:|---:|---:|
| Demonstrated need | 5 |  |  |
| Async suitability | 5 |  |  |
| Emergency dependence | 5 |  |  |
| Consultant supply | 5 |  |  |
| Local doctor readiness | 4 |  |  |
| Information availability | 4 |  |  |
| Outcome measurability | 4 |  |  |
| Governance complexity | 4 |  |  |
| Data burden | 3 |  |  |
| Partner support | 4 |  |  |
| Volume feasibility | 3 |  |  |
| Neutrality/access | 4 |  |  |

The weighting itself should be approved before scoring candidates.

## 5. Exclusion Criteria

A specialty should not be selected for the first pilot if any of the following remain unresolved:

- safe remote advisory boundary cannot be defined;
- most expected cases are emergency-dependent;
- insufficient consultant pool;
- no reliable partner facility;
- necessary diagnostic information cannot be obtained;
- legal/professional constraints make consultant participation impractical;
- outcome measurement is too weak to evaluate the model.

## 6. Evidence Required Before Scoring

Use evidence from:

- local-doctor needs survey;
- consultant survey;
- facility interviews;
- NGO/partner discussions;
- clinical-governance review;
- connectivity assessment;
- available referral patterns where known.

Do not score solely from founding-team opinion.

## 7. Recommended Decision Process

1. Shortlist 3 to 4 specialties.
2. Collect evidence using the same questionnaire.
3. Score independently by at least:
   - clinical lead;
   - operations representative;
   - technology/product representative;
   - evaluation/research representative.
4. Discuss large scoring differences.
5. Record rationale.
6. Select primary specialty.
7. Keep one backup specialty if partnership or regulatory conditions change.

## 8. Output

The final decision should produce:

- selected specialty;
- reason for selection;
- scorecard;
- known limitations;
- consultant-capacity assumption;
- facility assumption;
- minimum case template;
- specialty-specific safety boundaries;
- decision review trigger.

## 9. Scope Guardrail

Selecting a specialty does not expand Sanad into:

- emergency care;
- direct patient consultation;
- remote prescribing;
- national rollout.

The specialty must fit the existing Sanad scope, not redefine it.

## Required Expert Review

**Level:** Blocking before specialty selection.

**Experts required:**
- Clinical Governance Lead
- Relevant specialty experts
- Public Health / Health Services Evaluation specialist
- Operations representative

**Required evidence:** local-doctor needs data, consultant capacity, facility case volume, emergency dependence, remote-review suitability, and measurable outcomes.

The Project Manager should not approve a specialty from score alone without clinical interpretation.
