# Pilot Support Model

**Version:** 0.1  
**Status:** Draft

## 1. Purpose

Define how users receive help during the pilot without confusing technical support with clinical advice.

## 2. Support Categories

### Account and Access
- login;
- MFA;
- locked account;
- role/verification status.

### Workflow
- cannot submit;
- assignment issue;
- status confusion;
- outcome/closure issue.

### Connectivity and Upload
- weak network;
- failed upload;
- sync problem;
- duplicate concern.

### Technical Incident
- application error;
- outage;
- missing notification;
- performance issue.

### Security / Privacy
- suspected account compromise;
- wrong case access;
- lost device;
- accidental disclosure.

### Clinical Governance
- disputed advice;
- incident/near miss;
- complaint;
- second opinion.

Clinical governance questions must be routed to clinical governance, not answered by technical support.

## 3. Support Channels

Final channels TBD.

Potential:

- in-app support;
- support email;
- phone/approved messaging for urgent operational issues;
- facility coordinator.

## 4. Severity

### P1
Safety/security critical or broad outage.

### P2
Core workflow blocked for one/multiple users.

### P3
Non-critical functional problem.

### P4
Question, enhancement, minor usability issue.

## 5. Ownership

- Technology: platform defects, access technology, infrastructure
- Operations: routing/process questions
- Clinical Governance: safety, advice disputes, incidents
- Privacy/Security: data/security events
- Project Lead: partner and unresolved cross-functional escalation

## 6. Knowledge Base

Maintain short guides for:

- logging in;
- MFA;
- submitting a case;
- uploading attachments;
- responding to information request;
- recording outcome;
- connectivity troubleshooting;
- reporting an incident;
- security/lost-device response.

## 7. Support Data

Support tickets should avoid unnecessary clinical content.

Case reference is preferable to copying case narrative.

## 8. Handover

Support issues affecting clinical safety must be handed to the correct governance role with traceable ownership.

## 9. Pilot Metrics

Track:

- ticket volume;
- category;
- time to acknowledge;
- time to resolve;
- repeated causes;
- user group;
- connectivity-related percentage.

Support data should inform product improvement.
