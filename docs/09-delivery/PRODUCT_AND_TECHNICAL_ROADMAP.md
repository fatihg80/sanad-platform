# Product and Technical Roadmap

**Version:** 0.1  
**Status:** Draft

## Phase 0: Discovery and Foundation

Objectives:

- validate clinical workflow;
- confirm pilot specialty;
- confirm partner model;
- complete Build vs Buy vs Partner decision;
- resolve hosting/data-residency direction;
- complete core legal/privacy discovery;
- establish architecture and security baseline.

Outputs:

- approved PRD/SRS;
- clinical workflow;
- data/privacy requirements;
- threat model;
- C4 architecture;
- ADRs;
- implementation backlog.

## Phase 1: MVP Build / Platform Adaptation

Objectives:

- implement core provider-to-provider workflow;
- secure identity and access;
- support clinical files;
- build governance essentials;
- prepare pilot operations.

## Phase 2: Pilot Readiness

- user acceptance testing;
- security assessment;
- clinical safety review;
- training;
- support process;
- backup/restore exercise;
- incident tabletop;
- monitoring.

## Phase 3: Live Pilot

Measure:

- adoption;
- response;
- safety;
- workflow completion;
- consultant retention;
- technical reliability;
- connectivity failures;
- user burden.

Avoid major architecture expansion during the pilot unless required for safety or continuity.

## Phase 4: Evidence Review

Make explicit:

- Continue;
- Modify;
- Pause;
- Stop.

Assess:

- clinical value;
- safety;
- usability;
- operating cost;
- regulatory feasibility;
- sustainability;
- technology fit.

## Phase 5: Expansion

Only after evidence:

- additional specialties;
- more facilities/states;
- stronger routing;
- institutional integrations;
- expanded education/MDT;
- research capability.

## Phase 6: Mature Platform

Potential later capabilities:

- SSO/federation;
- FHIR/integration services;
- advanced policy/audit;
- SIEM;
- higher availability;
- multi-region architecture;
- native mobile where justified.

## Decision Rule

Scale the operating model first, architecture second.

Do not build national-scale technical complexity before the pilot proves the service model.
